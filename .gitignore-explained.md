# GitIgnore Configuration

This document explains the gitignore strategy for the AutoRescue project.

## Files Structure

```
AutoRescueAI/
├── .gitignore                          # Root gitignore (comprehensive)
├── AutoRescue-Backend/
│   └── .gitignore                      # Backend-specific patterns
└── AutoRescue-Mobile/
    └── .gitignore                      # Android-specific patterns
```

## What Gets Ignored

### **Secrets & Credentials (CRITICAL)**

These files are NEVER committed:
```
.env                                   # Environment variables
.env.local                             # Local overrides
*.jks                                  # Java keystores
*.keystore                             # Keystore files
debug.keystore                         # Android debug keystore
google-services.json                   # Firebase config
*.pem                                  # Private keys
*.key                                  # Encryption keys
*.p12                                  # PKCS12 certificates
```

**Why:** API keys, database passwords, signing keys must never be in version control.

### **Build Artifacts**

```
*.apk                                  # Android APK
*.aar                                  # Android library
*.aab                                  # Android App Bundle
build/                                 # Gradle build output
dist/                                  # Distribution packages
*.egg-info/                            # Python distribution
*.whl                                  # Python wheels
```

**Why:** Generated files take up space; can be rebuilt from source.

### **Cache & Temporary Files**

```
__pycache__/                           # Python cache
.gradle/                               # Gradle cache
.pytest_cache/                         # Pytest cache
.venv/                                 # Virtual environment
venv/                                  # Virtual environment
node_modules/                          # NPM dependencies
*.pyc                                  # Compiled Python
*.class                                # Compiled Java
```

**Why:** Regenerated on build; wastes repo space and causes merge conflicts.

### **IDE & Editor Configuration**

```
.idea/                                 # Android Studio
.vscode/                               # VSCode
*.swp                                  # Vim swap
*.swo                                  # Vim backup
*.sublime-project                      # Sublime Text
*.iml                                  # IntelliJ project
.project                               # Eclipse
.classpath                             # Eclipse
```

**Why:** Personal editor settings shouldn't force others to use same config.

### **OS-Specific Files**

```
.DS_Store                              # macOS
Thumbs.db                              # Windows
.directory                             # Linux
.Spotlight-V100                        # macOS
ehthumbs.db                            # Windows thumbnail cache
```

**Why:** OS-specific metadata unrelated to project.

### **Logs**

```
*.log                                  # General logs
fastapi.log                            # FastAPI server
backend.log                            # Backend logs
chat_test_results.log                  # Test output
android_build.log                      # Build output
logs/                                  # Log directory
```

**Why:** Runtime artifacts; regenerated with each run.

### **Database Files**

```
*.db                                   # SQLite database
*.sqlite                               # SQLite database
*.sqlite3                              # SQLite database
*.db-journal                           # SQLite journal
```

**Why:** Local test databases; production uses Supabase.

## What Gets Committed

These files ARE tracked in git:

```
✓ Source code (.py, .kt, .tsx)
✓ Configuration (build.gradle, pyproject.toml, package.json)
✓ Documentation (README.md, CLAUDE.md)
✓ Tests (test_*.py, *Test.kt)
✓ Dependencies list (requirements.txt, build.gradle)
✓ .gitignore itself
✓ CI/CD config (.github/workflows)
✓ Public configuration (gradle.properties template)
```

## How to Handle Secrets

### **For .env Files**

1. Create `.env.example` with template:
   ```env
   GROQ_API_KEY=your-api-key-here
   DATABASE_URL=postgresql://user:pass@localhost/db
   ORCHESTRATOR_AGENT_ADDRESS=agent1q...
   ```

2. Developers copy to `.env` and fill in their values:
   ```bash
   cp .env.example .env
   # Edit .env with actual values
   ```

3. `.env` is gitignored and never committed

### **For Keystores**

1. Generate Android keystore locally:
   ```bash
   keytool -genkey -v -keystore debug.keystore \
     -storepass android -alias androiddebugkey \
     -keypass android -keyalg RSA -keysize 2048 \
     -validity 10000
   ```

2. Keystore is gitignored; CI/CD uses signing config from secrets

3. For releases, use GitHub Secrets or similar

## Checking What's Ignored

Before committing, verify files are properly ignored:

```bash
# See what would be committed
git status

# See what's ignored (verbose)
git status --ignored

# Check specific file
git check-ignore -v .env

# Count ignored files
git clean -fdXn | wc -l
```

## Accidentally Committed Secrets?

If a secret was accidentally committed:

1. **Immediately rotate the secret** (API key, password, etc.)
2. Remove from git history:
   ```bash
   git filter-branch --tree-filter 'rm -f .env' -- --all
   git push --force-with-lease
   ```
3. Regenerate all secrets
4. Add to .gitignore

## Team Best Practices

✅ Always copy `.env.example` → `.env` on first setup
✅ Never modify `.env.example` with real secrets
✅ Document all required environment variables
✅ Use git hooks to prevent committing secrets:
   ```bash
   # Install git-secrets
   brew install git-secrets
   git secrets --install
   git secrets --register-aws
   ```
✅ Review `.gitignore` when adding new file types
✅ Test `.gitignore` rules in a temp directory

## CI/CD Considerations

- `.env.example` is committed (shows structure)
- `.env` is gitignored (never in repo)
- Secrets injected via environment variables in CI/CD platform
- GitHub Actions: Use `secrets.XXX` in workflows
- Docker: Build args passed at runtime, not baked in

## Troubleshooting

### File is not being ignored despite .gitignore rule

The file may already be tracked. Remove it:
```bash
git rm --cached <file>
git add .gitignore
git commit -m "Remove <file> from tracking"
```

### .gitignore changes not taking effect

```bash
# Clear git cache and reapply gitignore
git rm -r --cached .
git add .
git commit -m "Apply updated gitignore"
```

### Need to commit a gitignored file

Use force:
```bash
git add -f <file>  # Force add despite gitignore
```

Use only if intentional (e.g., committing a template `.env.example`)
